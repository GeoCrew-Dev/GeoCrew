# 同勘 GeoCrew Android 客户端

开源的野外地质移动工具：多图源底图、实时定位、野外记录与小组协同。

> 状态：早期开发。规划见 [geocrew-protocol](https://github.com/GeoCrew-Dev/GeoCrew-Protocol/blob/main/docs/roadmap.md)。

## 底图与天地图 Key

应用**不内置任何地图 Key**。天地图的个人 Key 有每日调用额度，多人共用一个 Key 很快就会被限流，所以每位用户使用自己的 Key：

1. 在[天地图官网](https://www.tianditu.gov.cn/)注册开发者账号，进入控制台创建应用，应用类型选「服务端」。
2. 打开同勘 → 设置 → 天地图 Key，粘贴后点「保存并校验」。

没有 Key 也能用：图层里可以选 OpenStreetMap 或空白底图，也可以在设置里添加任意 XYZ / WMTS（KVP）图源（地址模板支持 `{z}` `{x}` `{y}` `{-y}` `{s}`）。如果天地图拒绝请求（Key 无效、类型不对或当日额度用完），地图上会给出提示并建议切换图源。

**离线底图**：在设置里导入 MBTiles 栅格瓦片包（png、jpg、webp，可用 QGIS、MOBAC 等桌面软件导出），文件会解包到应用私有目录的 `basemaps/<id>/{z}/{x}/{y}.<ext>`，再以 `file://` 地址注册成一个图源，所以地图渲染不用区分在线和离线。超过包内最大级别时瓦片会放大显示；选用离线底图而当前视野不在其范围内时，地图会自动移到包的范围。矢量瓦片包（pbf）暂不支持。

**下载当前范围**：地图「图层」里可以把屏幕上的这片底图直接存成离线底图：选好缩放级别后先显示要请求多少张瓦片、大约多大，一次最多 2 万次请求，避免一下用完天地图 Key 当天的配额；四个请求并行，切到别的页面或锁屏也会继续（通知栏显示进度，可在那里暂停）。下载可以暂停后再继续，连续多次连不上服务器时会自动暂停；应用被关掉也不要紧，下次打开地图会提示没下完的底图，继续时只下还缺的瓦片（下载目录里的 `download.json` 记着范围和图源，不含 Key）。「取消并删除」会删掉已下的部分。瓦片存放方式与导入的 MBTiles 相同（每个图层一个子目录），完成后可一键换成这张底图。OpenStreetMap 官方瓦片服务的使用政策不允许批量下载，所以它不提供这个功能；天地图和自定义图源会提示遵守提供方的条款。计算瓦片范围的是 `core:model` 的 `TilePlan`，下载在 `core:data` 的 `BasemapDownloads`。

**叠加扫描图片**：「图层」里的「叠加图片」可以把扫描的地质图、前人的草图（JPG 或 PNG）铺在底图上，调透明度、开关、上下排序。同时选上它的 world 文件（.jgw、.pgw、.tfw、.wld）就按文件里的坐标四角定位：经纬度的直接用，高斯-克吕格坐标按横坐标前的带号判断是 3° 还是 6° 带（CGCS2000）；没有 world 文件或认不出坐标时，先按比例铺满当前视野，再点「对齐」用控制点校正：先点图片上认得出的地物，再点它在底图上的真实位置（也可以用十字中心取点），一对只平移，两对再加旋转和缩放，三对以上按最小二乘拟合仿射变换，能纠正扫描时的歪斜，并显示最大偏差，偏差大说明有一对点错了。也可以点「铺到视野」重新铺。图片最长边缩到 4096 像素以内存在本机，工程包会带上，但不会同步给工作组。world 文件的解析在 `core:model` 的 `WorldFile`，控制点拟合在 `OverlayAlign`，存图在 `core:data` 的 `OverlayImages`。

**图幅号**：按国家基本比例尺地形图分幅和编号（GB/T 13989-2012）。地图「图层」里可以打开 1:10万、1:5万、1:2.5万或 1:1万的图幅线，每幅中间标出新图幅号（如 J50E004003）；选中一个点时卡片上显示它所在的 1:5万图幅；「前往坐标」里输入图幅号（大小写、带不带横线都行）就移到那一幅。计算在 `core:model` 的 `MapSheet`，从 1:100万到 1:5000 都支持，旧式图幅号（如 J-50-5-B）暂不识别。

**地图缓存**：联网时看过的瓦片由 MapLibre 存在手机里，没信号时还能显示。设置里可以把缓存调到 50 MB、200 MB（默认）、500 MB 或 1 GB，也可以一键清空。出发前在有网的地方把测区按需要的缩放级别浏览一遍即可带进山里；这只是正常浏览产生的缓存，不做批量下载，不违反图源的使用条款。

## 编译

需要 JDK 17 和 Android SDK（compileSdk 35）。

```bash
./gradlew assembleDebug test
```

开发时可以在 `local.properties` 里写 `tianditu.key=你的Key`，它只会进入 debug 包作为默认 Key；release 包永远不带 Key。

每次推送到 `main`，GitHub Actions 会编译调试版 APK 并跑单元测试，APK 可在运行记录的 Artifacts 中下载。

### 工程

工程是应用的顶层容器。启动后先进入工程列表，打开一个工程才进入它的地图；记录、轨迹、照片、产状、分析结果、底图选择、上次的地图视图以及所绑定的工作组都属于工程。一个工程最多绑定一个工作组，绑定后只同步这个工程的数据。

跨工程的全局内容只有：天地图 Key 等账号信息、图源库（内置和自定义图源）、显示与测量偏好、昵称。新建工程时沿用最近一次选择的底图。

**存储方式**：所有工程共用一个 Room 数据库，业务表都带 `projectId`（外键级联删除），而不是每个工程一个库文件。理由：

- 工程列表的记录数、照片清理等需要跨工程查询，单库一条 SQL 即可；
- 只有一套迁移，升级时不会出现部分工程库没迁移的情况；
- Room 与 Hilt 按单例注入数据库，不必在切换工程时关闭、重开连接，也不会让后台同步和界面拿到不同的库；
- 工程的可移植性由「工程包」导出 / 导入解决，不依赖拷贝数据库文件。

**工程包**（`*.geocrew.zip`）：在工程列表的菜单里导出，右上角导入。包内是 `project.json`（名称、日期、工程设置）、`features.geojson`（全部记录）、`tracks/<id>.csv`（轨迹每个点的时间、精度、速度）、`photos/<sha256>.jpg`（照片）和 `audio/<sha256>.m4a`（录音），有叠加图片时还有 `overlays/<sha256>.jpg`（或 .png）。不含工作组链接和凭据。导入时总是新建一个工程并给记录分配新 ID，所以同一个包可以反复导入，也能直接交给别人。格式说明见 `core:formats` 里的 `ProjectPackage`。已连接工作组的工程可以在工作组页点「下载整组数据」，从服务器取回全组的记录、照片和表单，存成同样格式的工程包（需服务端支持 `package` 能力）。

**记录表单**：在工程菜单的「工程设置与表单」里为工程定义一组属性（文字、数字带单位、选项），可以限定只用于某些记录类型，也可以一键套用「地质填图」模板（点号、地层、构造类型、样品编号、厚度）再按需修改。记录详情会把这些属性排在最前面，数字弹数字键盘、选项用下拉。值照常写进记录的 GeoJSON 属性，所以导出、同步、分析都不需要额外处理；文字型的值始终按文字保存，样品号 `007` 不会变成 7。属性可以设为「必填」：没填的在详情里标出，记录列表多一个「待补全」筛选并在每条下面写明缺哪几项，收工前扫一遍即可；只是提醒，不会阻止保存或同步。

**三点法求产状**：同一层面（接触面、煤层、断层面）上选三个点，用定位海拔或某个高程属性，在局部平面坐标里求过三点的平面，给出倾向、倾角和走向，结果作为带产状的点放在三点中心，可直接参与赤平投影和剖面投影。三点几乎共线（三角形最小角小于 5°）时拒绝计算。算法在 `core:gis` 的 `ThreePointTool`。

**极点等密图**：赤平投影页选「等密图」，按 1% 面积计数法画极点等密线，从 1% 起逐级加倍（数据很分散时从 0.5% 起），均匀分布时处处约为 1%。计数用与 1% 计数圆面积相同的 Fisher 核（κ = 100）做平滑，几十个读数也能画出平滑的等密线；极点按轴处理，靠近基圆的读数会同时算到对侧。算法在 `core:gis` 的 `Stereonet.density`。

**褶皱枢纽**：赤平投影页对极点做方向张量特征分析（Woodcock 1977），给出分布形态（K 值大于 1 为集中、小于 1 为环带，强度 C 小于 2 视为分散）。极点呈环带分布时按圆柱状褶皱处理：最小特征向量就是枢纽（π 轴），图上画成红色三角，最佳拟合大圆（π 圆）画成虚线，概要里给出枢纽的倾伏向和倾伏角。算法在 `core:gis` 的 `Stereonet.fabric`。

**岩性建议**：地质点的岩性一栏下面有一排候选词，先列本工程已经用过的写法（用得多的在前），再列常见岩浆岩、沉积岩、变质岩和松散沉积名称，输入时按包含关系筛选。一个组统一写法后，赤平投影按岩性分组才不会把「灰岩」「石灰岩」拆成两组。词表在 `core:model` 的 `Lithology`。

**定点平均**：设置里「定点」可选 10、30 或 60 秒。打开后在地图上点「定点」，会连续定位这段时间，按每次的精度加权平均（差于 30 米的定位不用），地图顶部显示进度和离散程度，可提前「现在打点」。记录里存下单次定位精度（取中位数，不按次数缩小，因为短时间内的 GPS 误差高度相关）、平均次数和离散距离，详情页可以看到。

**记录编号**：新记录按前缀加顺序号命名（默认地质点 D001、普通点 P001、线 线001、面 面001），接着本工程已用过的最大编号往下排，删掉中间的记录也不会重号。前缀和位数在工程设置里改，只存在本机，所以一个工作组里每人可以用自己的前缀（例如 D-王001），离线各自打点也不会撞号。

**CSV 属性表**：在「导入导出」里可以把记录导出成 CSV（带 BOM，Excel 直接打开不乱码），表单属性排在前面并用表单里的名称做列名；也可以导入带经纬度列的 CSV（列名可以是 lng/lat 或 经度/纬度，逗号、分号、制表符分隔均可），批量放入计划点位。导出的 `id` 列再导入时会更新原记录而不是重复添加。

**导入 Shapefile**：把 .shp、.dbf、.prj（有 .cpg 更好）打成一个 zip，在「导入导出」里导入，一个包里可以有多个图层，每条记录带上 `layer`（图层名）属性。坐标可以是经纬度，也可以是横轴墨卡托 / 高斯-克吕格投影（CGCS2000、WGS 84、西安 80、北京 54 椭球，3° 或 6° 带都按 .prj 里的中央经线和东偏移换算）；缺 .prj 时按数值判断经纬度或带带号的高斯坐标，判断不了就提示。西安 80 和北京 54 不做基准转换，会提示可能偏几十到一百多米。属性表的中文按 .cpg 声明的编码读，没有声明时先试 UTF-8，不行再按 GBK（国内多数 GIS 软件的默认）；名称、编号一类的列作为记录名，和表单名称相同的列直接进表单字段。读取在 `core:formats` 的 `ShapefileReader`。

**导出 DXF**：给 AutoCAD、MapGIS 等制图软件用的 R12 版 DXF，坐标是 CGCS2000 3° 带高斯坐标（X 为带带号的横坐标，Y 为纵坐标，整份文件用记录中部所在的带，文件开头的注释写明带号和中央经线）。有图例时按图例分图层并取最接近的 CAD 标准色，没有时按记录类型分图层；记录名放在「注记」图层，产状画成走向线加倾向短线和倾角，放在「产状」图层，符号大小按 1:1 万出图设计。中文按 GBK（代码页 936）写入，国内 CAD 打开不乱码。

**GeoPackage**：「导入导出」里导入导出 OGC GeoPackage 1.3（`.gpkg`，QGIS、ArcGIS 都能直接打开）。导出时点、线、面各一张表（`points`、`lines`、`polygons`，EPSG:4326），固定列有记录号、类型、名称、岩性、产状、线型、颜色等，表单属性按表单里的名字各占一列（数字类型存成数值），`properties` 列存全部属性的 JSON，所以再导回同勘不丢东西；表结构与服务端的 `export.gpkg` 一致。导入时读每个要素图层，经纬度（WGS 84、CGCS2000 等）和高斯-克吕格投影都认，列名能对上表单的就按表单属性存，每层最多 5 万个要素。GeoPackage 是 SQLite 库，`core:formats` 不依赖安卓，只声明要用的 `SqlEngine`，应用启动时注入安卓自带的 SQLite 再注册这个格式，测试里用 JDBC 驱动；别的需要平台能力的格式也可以这样用 `FeatureFormats.register` 加进来。

**集合点**：任何点记录的详情里填一个集合时间（如 17:30，已经过了一小时以上就算明天），它就成了全组的集合点（协议 §6.8 `meet_at`）。地图上集合点外面有一圈紫色环，顶部提示下一次集合的时间、还剩多久、离你多远在哪个方向，点「看位置」跳过去，「详情」里能寻点前往；过了时间还会显示一小时。网页查看页同样置顶提示。

**方位交会**：工具页的「方位交会」用罗盘方位定点。前方交会：在两三个已知点（工程里的点记录，或「我的位置」）上量向同一目标的方位，求出过不去的露头、对岸崖壁的位置；后方交会：站着不动，量向两三个已知地物（山顶、三角点、已定的点）的方位，在 GPS 信号差的沟谷里求出自己的位置。方位可以手输，也可以竖起手机用后摄像头对准后点「读罗盘」；磁方位按磁偏角改正。两条视线直接求交点，三条以上用最小二乘，并给出视线的最大偏离，看读数准不准；交会角小于 30° 或交点落在站点背后（多半方位读反了）会提醒。结果可以存为地质点，备注里记下用了哪几个点和方位，精度按偏离估。算法在 `core:model` 的 `BearingFix`。

**审核**：组长在记录详情的「审核」里点「通过」，或「退回…」写上要改什么（协议 §6.9 `review`）。退回的记录进组员的「待核对」，列表里通过的标「已审核」；审核之后记录又被改过会提示「之后有改动」，方便组长再看一遍。只有组长能改审核：组员的修改照常同步，服务端保留原来的审核。网页查看页的记录弹窗里也显示审核。

**地质界线与断层**：线记录详情里可以标成实测地质界线、推测地质界线、实测断层或推测断层（再点一下取消），地图上界线画黑色、断层画红色粗线，推测的画虚线，网页查看页画法相同（协议 §6.7 `line_style`）。标了线型的线也可以填产状（断层面、界面的倾向倾角），产状符号画在线的中点，点一下符号就选中这条线。导出 DXF 时这些线各自放在以线型命名的图层上，推测的图层用虚线线型。DXF 和网页查看页里的线上产状同样放在中点。

**地图图例**：同在「工程设置与表单」里，选一个属性（岩性，或表单里的文字、选项属性，比如地层）给地图上的记录着色，像地质草图那样一眼分出岩性和地层。选好属性会自动列出记录里已用的取值和选项的各个值，按岩石名配上常用颜色（花岗岩粉、砂岩黄、灰岩蓝、片岩紫等），不认识的依次取色板颜色，每个都可以改。地图左下角显示当前视野里用到的图例项，点一下收起。自带颜色的记录（分析结果、导入文件里的 simplestyle）保持原色。绑定工作组时图例和表单一起放在共享设置里（键 `legend`），组长改了全组地图同步变色。导出 KML 时同样按图例给每条记录配上样式，在奥维互动地图、Google Earth 里打开是同一套颜色。

绑定工作组的工程，表单以工作组为准（协议 §2.2 共享设置）：组长修改后同步给全组，组员只读；两位组长同时修改时，后提交的一方会收到提示并拿到最新版本，而不是悄悄覆盖。离线时组长的修改先存在本机，下次连上再发布。服务端不支持共享设置时，各自保留本机表单。

工程自己的设置（底图、地图视图、说明、表单等）以 JSON 存在 `projects.config` 列，新增字段无需数据库迁移，旧版本读取新版本写的内容时会忽略不认识的字段。

### 添加分析工具

实现 `core:gis` 里的 `GisTool` 接口（声明参数、读取要素、返回新要素和说明），再在任意模块用 Hilt 注册：

```kotlin
@Provides @IntoSet fun myTool(): GisTool = MyTool()
```

分析界面会按参数（数字、属性、选项、某条记录）自动生成表单，结果作为普通记录保存，可同步、可导出。输出要素可用 GeoJSON simplestyle 属性（`fill`、`stroke` 等）指定颜色。

**其他应用提供的分析工具（插件）**：不想改同勘代码，也可以单独做一个安卓应用当插件，用任何语言实现分析。插件声明一个接收 `org.geocrew.plugin.action.RUN_TOOL` 的 Activity 和一个 JSON 说明（参数类型同上），同勘运行时把符合条件的记录写成 GeoJSON 交给它，插件把结果 GeoJSON 写回。插件工具和内置工具出现在同一个列表里，结果同样可保存、同步、导出。接口规范见 geocrew-protocol 的 `docs/plugins.md`，平台无关的部分在 `core:gis` 的 `ExternalTool`，安卓端的查找与启动在 `feature:analysis` 的 `PluginTools`、`PluginHost`。`samples/plugin` 是一个可安装的示例插件（为线和面求中心点或外接矩形），只用系统自带的 `org.json`，不依赖同勘的任何代码。

**克里金与补点建议**：克里金工具先算实验半变异函数，再按点对数加权拟合球状、指数或高斯模型（块金、基台、变程会写在结果里，变程也可以手动指定），用最近 16 个点做普通克里金。网格可以按估计值或估计标准差着色；后者直接告诉你哪里最没把握。「建议补点数」大于 0 时生成补点计划：克里金方差只取决于采样点在哪、与测值无关，所以每选出一个补点，就把它当作已经采过、重新计算周围的方差，再选下一个，补点自然散开而不会扎堆在同一片空白里；「兼顾路程」时离上一个点近的位置优先，用少许信息量换更短的路。选了「补点路线起点」（如驻地或现在所在的记录点）后，各补点按最短顺序（最近邻加 2-opt）编号，并画出一条补点路线、给出直线距离。补点和路线都是普通记录，可以同步给组员、用「寻点」走过去。算法在 `core:gis` 的 `SamplingPlan`。

**等值线**：IDW 和克里金在出网格的同时画等值线（行进方格法，鞍点按格心均值判断，无数据格处断开），间距留空时按 1、2、5 的整倍数自动分成约 8 档，填 0 则不画。克里金按当前显示的量画，选「估计标准差」就是方差等值线。等值线是普通的线要素，标题写成「Cu = 120」，可以导出到 KML、GeoJSON。算法在 `core:gis` 的 `Contours`。

**剖面投影与视倾角**：选一条线作为剖面线（方向从起点到终点），工具把两侧投影带内的产状点投到线上，按 tan β = tan δ · cos(剖面方位 − 倾向) 算出视倾角，结果按到起点的距离排好。每个投影点存为一条记录，属性里有 `chainage_m`（距起点）、`offset_m`（离线距离，右侧为正）、`apparent_dip`（正值向剖面前进方向倾）和原始产状，可以直接导出 CSV 拿去画剖面图。参数里的「选一条记录」是 `ToolParam.Feature`，自己写的工具也能用。

**图切剖面**：同样选一条剖面线，工具从起点走到终点，依次列出穿过的填图单元（面，按所选属性如岩性或地层代号命名，不选就用面名）和每段的起止距离、长度，以及切过的地质界线、断层（线）的位置；界线有产状时一并算出剖面上的视倾角。面重叠时取小的那个（岩脉画在围岩上时读成岩脉），相邻的同一单元合并成一段，不在任何面里的部分在说明里给出合计长度。结果是按单元着色的剖面分段和交点，属性里有 `from_m`、`to_m`、`chainage_m`、`apparent_dip`；分析页还按比例画一条「剖面示意」，单元按颜色分段，界线和投影的产状按视倾角画短线，两种剖面工具都有。算法在 `core:gis` 的 `MapSectionTool`。选「取公开 DEM 高程」时（默认），还沿剖面线每约 30 m 取一个地面高程，输出一条地形线；剖面示意随之画成剖面草图：地形线、贴着地面的单元色带，界线和断层从出露点按视倾角画进地下，垂直放大倍数自动选并标出。高程取自公开的 Terrarium 地形瓦片（AWS Terrain Tiles，Mapzen 整理的 SRTM 等数据，约 30 m 分辨率），瓦片缓存在本机，同一带再算不用联网；没网时剖面照常出，只是不画地形。有地形线时可「导出剖面图 PDF」：A4 横版一页，水平取能放下的整数比例尺（如 1:1万），垂直比例按放大倍数标出，画高程与距离坐标、地形线、单元色带与名称、界线和断层的名称与视倾角，附图例，供野外整理或报告插图。

**地形分析**：画一个面圈出测区，工具在面里按格网（默认约 30–60 m，随面积自动放大）取公开 DEM 高程，可输出三种结果：等高线（等高距按高差自动选，也可手填，每五条加粗为计曲线）、坡度分级（0–5°、5–15°、15–25°、25–35°、35–45°、45° 以上，按色着到格子上）、坡向（八个方向加平地）。说明里给出最高、最低、平均高程和平均坡度，坡度和坡向还列出面积最多的几级。踏勘前看哪里陡、选上山路线，或者给没有等高线的底图补一套。算法在 `core:gis` 的 `TerrainTool`，高程来源与图切剖面相同，取过的瓦片离线也能再算。


**地层厚度**（工具页）：填岩层产状和从一侧界线量到另一侧的导线（每段方位、坡角、斜距，上坡为正），给出真厚度、铅直厚度和水平出露宽度。导线可以斜交走向、分几段，也可以直接选两个记录点（有海拔时按高差算坡角）。计算是导线向量在岩层法向上的投影 h = |n · Σv|，课本里「坡向与倾向相同/相反」等分情况的公式都是它的特例，见 `core:model` 的 `ThicknessResult`。

**地质路线**（工具页）：一天的路线调查记成一条「地质路线」记录：路线号（L001 起自动续号）、日期、参加人员、目的与任务，按走过的顺序排好地质点，每两点之间写点间（路线）描述，最后写路线小结。新建时自动填入当天按记录时间排好的点，也可以手动挑点、上下调整、移除。点仍是普通记录，路线只按 id 引用它们（协议 §6.6），改点不影响路线，删掉的点自动不计；地图上把各点连成一条路线，记录详情里可以再打开编辑。导入导出页的「地质路线记录表（CSV）」每条路线一个目的行、每点一行（位置、岩性、产状、点上与点间描述）和一个小结行，可整理成野外记录簿。

**实测剖面**（工具页）：沿剖面拉皮尺，依次记下每段导线的方位、坡角和斜距，再记每个分层的终点（整条导线上的累计斜距）、岩性和产状；岩性会提示工程里用过的写法，产状可以直接取某条记录的。各层真厚度随输入即时算出，没有实测产状的层借用最近一层并注明，导线在层内折返也会提示；下面是按真实比例画的剖面草图，分层界线标在导线上。起点用当前位置或某条记录的位置，保存后剖面作为一条「实测剖面」记录同步给组员（协议 §6.5），地图上画出推算的剖面线，记录详情里可以再打开编辑。导入导出页的「实测剖面分层表（CSV）」每层一行，可做剖面登记表，野外记录报告里也列出各层厚度；计算在 `core:model` 的 `MeasuredSection`。

**柱状图**：实测剖面列表里每条剖面右侧的 PDF 按钮把它画成 A4「实测剖面柱状图」：层号、柱状图、累计厚度、厚度、岩性及描述（含产状和备注），各层按真厚度在同一比例尺下堆叠，比例尺从 1:50 到 1:5 万里自动选能放进一页的最细一档，太薄的层按最小高度画并注明，放不下时接着下一页、表头重复。导出前选导线是自下而上测（第 1 层在底）还是自上而下测。岩性按名称配花纹（砂岩点、粉砂岩点加短线、泥页岩短线、灰岩砖块、白云岩斜砖、泥灰岩砖块加短线、砾岩圆圈、煤涂黑、侵入岩十字、火山岩 v 字、变质岩波纹），按中文岩石名以最后的主名词为准，所以「凝灰岩」不会被当成灰岩、「白云质灰岩」算灰岩；页尾附所用花纹的图例。排版在 `core:formats` 的 `StratColumn`（纯 Kotlin，可单测），绘制在 `feature:compass` 的 `StratColumnPdf`。

**坐标换算**（工具页）：经纬度与高斯-克吕格平面坐标（X 北、Y 东，Y 可带带号）互换，按国家标准分 3° 带和 6° 带，椭球可选 CGCS2000、WGS 84、西安 80、北京 54。输入可以粘贴、用当前位置或选记录点；也能把当前工程的全部点导出成平面坐标 CSV 表。投影用 Krüger 六阶级数（`core:model` 的 `TransverseMercator`），与 PROJ 结果对到毫米。北京 54、西安 80 只换椭球，不做基准转换。

**寻点**（工具页，或点记录详情右上角的箭头）：选一个点记录，屏幕上的箭头随手机转向指着它，并显示距离、方位、还要向左或向右转多少度、高差。指派给自己且未完成的任务点排在最前。走到点位（5 米内，定位精度更差时按精度算）显示「已到达」，可直接打开记录改任务进度。

**日出日落**：工具页按当前位置（定位前用地图视野中心）算出今天和之后 6 天的民用晨光、日出、正午、日落和民用昏影时间，并显示距日落、天黑还有多久，方便安排收工。用 NOAA 太阳位置公式，北京冬夏至与公开时刻相差不到 2 分钟；不考虑地形遮挡。

**照片信息**：每张照片单独记下拍摄方向、位置和时间（协议 §6.2 的 `photo_info`）。相机写进 EXIF 的 GPS、时间和真北方向优先；相机没写的，用按下「拍照」那一刻手机后摄像头朝向的水平方位和当时的定位补上（相机应用打开后系统不再给后台应用传感器数据）。缩略图角上标出拍摄方向；点开照片可以看完整信息，或另存一张底部印有记录名、工程、坐标、海拔、方向和时间的照片到相册 Pictures/GeoCrew，原图不改。

**录音**：记录详情里「录一段」口述观察现象，单声道 AAC（约每分钟 0.5 MB），每段最长 10 分钟。录音和照片一样按内容哈希存储，记下时长、开始时间和当时位置（协议 §6.3 的 `audio`、`audio_info`），随同步上传给组员，也会放进工程包的 `audio/` 目录；野外记录报告里列出每条记录的录音段数和总时长。附件的种类集中定义在 `core:model` 的 `AttachmentKind`，以后加草图等新附件只需加一项。

**样品登记**：记录详情里「添加样品」，编号按记录名自动续排（D012-1、D012-2…），在整个工程里不能重复；类型可点常用的（薄片、岩石化学、同位素年龄等）或自己写，另有备注。一个点可以登记多件样品，存在记录的 `samples` 列表里（协议 §6.4），随记录同步。导入导出页的「样品清单（CSV）」每件样品一行，带编号、类型、所在记录、坐标、岩性和采样时间，按编号自然排序，可直接改成送样单；野外记录报告里也列出每条记录的样品。「样品标签（PDF）」把每件样品排成 A4 纸 3 × 8 的不干胶标签：编号、类型和岩性、点号和日期、坐标、工程名，右侧是编号的二维码（矢量绘制，打印不糊）；标签内容和排版计算在 `core:formats` 的 `SampleLabels`、`LabelSheet`，换标签纸只需改几个尺寸。

**分析结果回填**：化验结果回来后，在导入导出页「导入分析结果」选结果表（CSV，Excel 另存即可，UTF-8 或 GBK 都能读）：一列样品编号（列名如「样品编号」「样号」「Sample」），其余每列一个分析项，第二行可以是单位行（会并进列名，如 `Cu(ppm)`），低于检出限写成 `<0.05`。按编号（不分大小写）对上已登记的样品后先预览：对上多少件、哪些编号找不到、哪些列名和应用自带属性重名而跳过。确认后结果存到各样品的 `results` 里（协议 §6.4），同一记录各样品的平均值写成记录的数值属性（低于检出限按一半计），所以马上就能在地图图例、统计和 IDW/克里金插值里选用。解析在 `core:formats` 的 `AssayCsv`，匹配和写入在 `core:model` 的 `AssayPlan`。

**照片落点**：用单反或运动相机拍、或手机关了定位拍的照片，回来在导入导出页「照片落点」一次选多张：照片自带 GPS 的直接落点；没有的按 EXIF 拍摄时间对到当前工程同一时间记录的轨迹上（两次定位间隔不超过 10 分钟时按时间插值，轨迹中断时只用前后 2 分钟内的定位），可填相机时钟快几分钟来校正。每张照片成为一个照片点，已在工程里的照片不会重复导入。落点算法在 `core:model` 的 `PhotoGeotag`。

**野外记录报告**：「导入 / 导出」里可以把当前工程的记录生成一份 A4 PDF，按日期分组，每条列出位置（或线长、面积）、海拔、产状、岩性、表单属性、任务和备注，可选附每条最多 3 张照片和拍摄方向。可只导出今天的记录，适合收工后整理野外记录簿。坐标按设置里的格式显示。

**图层显示**：地图右侧「图层」里除了换底图，还可以按类型隐藏记录（比如先关掉轨迹）、在放大后显示记录名称、关掉组员位置，或在工作组里只看指派给自己、还没完成的任务。这些设置跟着工程走，只影响显示；有记录被隐藏时地图顶部会提示。

**移动点与改形状**：在地图上点选一条记录，卡片上的铅笔按钮进入编辑。点记录点地图上的新位置或用十字中心「移到中心」；线和面先点一个节点选中它（变成实心大圆），再点地图把它移过去，点线段旁边插入节点，线的两端外侧点一下就是延长，选中后还能删节点，每一步都能撤销。保存后照常同步，原来的形状留在记录的修改历史里可以恢复。移动超过 30 米的点不再保留原来的海拔，所有手动移动的点都去掉原定位精度和平均定位信息，免得「待核对」按旧精度判断。轨迹、实测剖面和地质路线的线是算出来的，不在地图上改。判断与插点在 `core:model` 的 `VertexEdit`。

### 小组协同

在「工作组」页面填写自部署服务端地址：组长新建工作组后，可以把邀请分享到聊天软件，或出示二维码；组员用相机扫码、点开 `geocrew://join` 链接或粘贴收到的邀请，加入表单就会自动填好。当前工程的记录、照片会在后台同步，组员位置显示在地图上，身后带一条最近半小时走过的细线（只用这次打开应用后收到的位置，不在服务端保存；位置共享默认关闭，可随时开关）。成员列表里每人显示今天的记录数、样品数和轨迹长度，顶部有全组合计，按已同步的记录统计（协议只记最后编辑者，别人后改过的记录算在后改的人头上）。成员凭据只保存在本机且不参与系统备份。

**讨论与组内消息**（协议 §8）：绑定工作组后，每条记录详情底部有讨论区，组员打开同一条记录就能看到；地图右侧的消息按钮进入组内消息，汇总发给全组的消息和各记录下的讨论，点一下记录讨论直接打开那条记录。发消息时可以附上地图中心位置，组员点开即在地图上标出。没信号时也能写，标为「待发送」，联网后自动发出；自己的发言和组长都可以长按删除。只读成员只能看。

**任务指派**（协议 §6.1）：绑定工作组后，记录详情里可以把这条记录指派给某位组员（例如组长先画好采样点再分下去），组员把它标成待办、进行中或已完成。记录列表多了「我的任务」「未完成任务」两个筛选。指派就是记录上的普通属性，没信号时也能改，联网后随记录同步；离线时只能指派给自己。地图上，指派给自己且未完成的记录外面有一圈橙色光晕。

**紧急消息**（协议 §8.1）：组内消息页右上角「紧急」用于求助或要求集合，只读成员也能发。消息自动附上当前定位（15 秒内拿不到定位时用地图中心并提示），没信号时先存手机里，联网后立即发出。组员这边：6 小时内的紧急消息在地图顶部置顶显示，可「看位置」「回复」或「知道了」；开了后台通知的会收到「紧急消息」渠道的高优先级提醒（带振动），不受通知设置里的类型筛选影响。

**点名**（协议 §8.2）：组长在组内消息页右上角「点名」发出要求（默认「收工了，请大家报平安」），全组收到提醒，地图顶部和消息页顶部出现点名卡片，一键「报平安」或「需要帮助」，回应自动附上当前位置；「需要帮助」同时是一条紧急消息，全组都会收到高优先级提醒。发起的组长在消息页看到已回应几人、谁需要帮助、谁还没回应（名单来自成员列表，没信号时只列已收到的回应），点一行可在地图上看这个人回应时的位置，结束点名后卡片从大家屏幕上消失。回应只通知发起的组长，不会打扰其他人。逻辑在 `core:sensors` 的 `RollCallActions`，点名状态来自 `core:data` 的 `TeamComments.rollCall`。

**后台通知**（协议 §9）：服务端开启推送时，工作组页会出现「后台通知」开关。通知走 [UnifiedPush](https://unifiedpush.org/)：手机上装一个分发应用（如 ntfy，可连自建的 ntfy 服务），同勘把分发应用给的地址登记到工作组服务器，有新的组内消息、记录讨论或指派给你的任务时就在通知栏提醒，不依赖谷歌服务。通知里只有类型和编号，内容仍通过正常同步取回，并按 RFC 8291 加密。每个工程单独登记，可同时关注多个工作组；退出工作组时自动注销。实现见 `feature:team` 的 `push` 包。

**在电脑上查看**（协议 §10）：服务端支持时，工作组页有「在电脑上查看」。选好有效期（2 小时到 7 天）生成一个只读链接，复制或分享到电脑，用浏览器打开就能看到全组记录、照片、录音和组员实时位置，也能下载 GeoJSON 或工程包。链接不能修改任何东西，也不会让你显示为在线；同一个对话框里可以撤销自己生成的全部链接，被移出工作组时链接一并失效。

构建约定集中在 `build-logic`（`geocrew.android.library`、`geocrew.android.feature` 等插件），新增模块只需几行配置。
