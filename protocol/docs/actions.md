# 动作层与 AI 助手

本文说明客户端如何把功能交给语音口令和 AI 模型来操作，以及权限怎样分级。这部分完全在客户端实现，服务端不需要任何改动；只有组长的限制和记录规则通过共享设置（协议 2.2 的 `ai_limits`、`record_rules`）同步给全组。

## 1. 动作

应用的每个功能都登记成一个「动作」：名字、说明、用 JSON Schema 写的参数、风险类别，以及在哪些页面提供。所有动作在同一个地方执行，每次执行都记入本机的操作日志，改动记录的动作先存下改动前的样子，所以每一步、或一次请求里的所有步骤都能撤销。

给模型用的是粗粒度的复合动作，一次调用办完一件事，例如 `place_point` 一次带上点号、岩性、产状和描述，而不是先打点再一项项改。模型一次回复可以提出多个动作。只把当前页面用得上的动作交给模型，当前工程、打开的记录、定位和轨迹状态写在系统提示里，省得模型先查。

目前的动作：

| 动作 | 作用 | 类别 |
| --- | --- | --- |
| `find_records` / `get_record` | 按条件查记录、读一条记录 | read |
| `open` | 打开地图、记录列表、某条记录或工作组页 | read |
| `place_point` | 在当前位置打一个地质点，可带点号、岩性、产状、描述 | edit |
| `update_record` | 改一条记录的名称、岩性、产状、描述，或在描述后追加 | edit |
| `add_sample` | 给记录登记样品 | edit |
| `set_attribute` | 改属性；一次改多条时算批量 | edit / bulk |
| `start_track` / `stop_track` | 开始、停止轨迹 | edit |
| `take_photo` | 打开相机给记录拍照 | edit |
| `delete_records` | 删除记录（可在「最近删除」恢复） | delete |
| `send_team_message` | 发组内消息，可标紧急 | send |
| `undo_last` | 撤销上一步 | edit |

新功能要让助手能用，只需登记一个动作并在执行处实现；界面、权限和日志不用改。

## 2. 常用口令

「定点」「打个点」「开始轨迹」「停止轨迹」「拍照」「撤销」以及产状（「120∠35」「倾向一百二十倾角三十五」「120 度 35 度」）在手机上按规则直接识别，不经过模型，断网也能用，算用户自己的操作。说「定点」时缺的项按工程记录规则逐项追问（点号、岩性、产状、描述，可说「跳过」），定完提醒拍照并可直接调起相机。可以打开语音播报，并开启「免手持」：读完一个问题自动听回答。

## 3. 风险类别与权限

| 类别 | 内容 | 默认 |
| --- | --- | --- |
| `read` | 查看和查询 | 直接执行（不能改） |
| `edit` | 新建和修改（可撤销） | 直接执行 |
| `bulk` | 批量修改 | 先问我 |
| `delete` | 删除 | 先问我 |
| `send` | 对外发送（组内消息、全组推送、上传） | 先问我 |
| `settings` | 改设置、密钥和工作组成员 | 先问我 |

每个类别用户可选「直接执行」「先问我」「禁止」。需要确认的步骤合在一张确认卡上，一下批准；也可以选「本次对话都允许」。判断顺序：

1. 用户自己点按和说出的口令直接执行；
2. 组长在 `ai_limits` 里禁止的类别不执行；
3. 用户设为「禁止」的不执行；
4. 查看和查询直接执行；
5. 模型读到记录或文件里的文字之后提出的改动、删除和发送，一律先确认（记录里的文字只当作资料，不当作指令）；
6. 设为「直接执行」或本次对话已允许的执行；
7. 其余的先确认。

一次请求最多 12 个动作，每分钟最多 40 个，超出的不执行。

## 4. 模型来源

模型来源是一个可替换的接口。现在提供「云端接口」：用户自己填任何兼容 OpenAI 的接口地址、模型名称和 API Key，Key 只加密保存在本机，不进工程包，不随工作组同步，应用里不内置任何 Key。以后计划加：

- 手机上运行的本地模型（GGUF 格式，llama.cpp）；
- 针对野外记录专门训练的小模型。

没有配置模型时，常用口令和引导式定点照样能用。
