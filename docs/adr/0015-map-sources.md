# 0015 地图图源

## 背景

地图要对标奥维，但项目方不提供统一 Key，也不分发地图数据。国内地图还涉及加偏坐标（GCJ-02 / BD-09）和审图号。

## 决定

- **用户自带 Key**：
  - 内置预设只收官方、带 Key 的服务：天地图、MapTiler、Mapbox、ArcGIS、Azure Maps、谷歌地图平台的瓦片接口。
  - 不需要 Key 的公开源（OSM 在线瓦片、AWS 地形数据）保留为可选预设，由用户直接连接提供方。
- **通用图源引擎**：
  - 支持 XYZ / TMS、WMTS、WMS、矢量瓦片（含 PMTiles）、MBTiles、GeoTIFF / COG；
  - 地址里可以带 `{key}`、子域名和请求头；
  - 用户可以自己添加图源，也可以导入或分享图源文件。
- **不托管、不分发任何地图数据**：离线底图和地名库只提供工具，数据由用户自备。
- **默认底图用天地图**，显示审图号。
- **GCJ-02 / BD-09 做成可选项**，默认关闭：
  - 显示时把我们的数据和定位点加偏后叠上去；
  - 在地图上点选位置时，反算回真实坐标；
  - 存储和导出永远用真实坐标（WGS84 / CGCS2000）；
  - 百度用的是自己的切片方式，要单独处理。
- **开车导航交给高德、百度**：通过它们的跳转接口传真实坐标，由它们自己换算（高德用 `dev=1`，百度用 `coord_type=wgs84`）。我们自己只做野外步行导航。

## 理由

只提供接口、由用户自带 Key，在法律上最稳妥，也符合"数据自主"的原则。加偏坐标在技术上可行，负责人的要求是"可行就做"。

## 代价与后果

- 用户要自己去申请 Key，使用门槛高一些，可以让 AI 帮着配置。
- 加偏的风险在法规上，不在技术上：反算用的不是官方公开的算法。只在 GitHub 发布能降低风险，但风险不是零。
- 待定：天地图瓦片能不能离线缓存，要先查清它的服务条款。

## 状态

已采纳（2026-11-25）。M1 验证了 GCJ-02 / BD-09 的加偏显示和反算精度：正向加偏逐点计算，反算迭代 5 次误差在微米级；百度瓦片要整套重投影，往后放，见[验证报告](../spikes/m1-gcj.md)。

2026-11-27 补充：负责人定了"合规的就做，不合规的不做"。
- **地图缓存**：做了。MapLibre 按图源服务器给的缓存头存看过的瓦片，和浏览器一样，不预先抓取、不违反服务器的规定。设置里可以调上限（默认 500 MB，可选 100 MB 到 2 GB），能看已用多少、一键清除。
- **把在线图源批量下载、转成栅格文件**（给某个范围出 GeoTIFF、MBTiles）：技术上 GDAL 能做，但先不做。谷歌地图瓦片 API 的政策明确禁止预取、存储和离线使用；天地图能读到的地方站条款写着未经书面许可不得复制、镜像服务内容，全国站的用户服务条款（uums.tianditu.gov.cn/provision）从开发环境打不开，没能核对。以后只对条款明确允许下载的图源做（用户自己的 WMS / 瓦片服务等），天地图要查清全国条款或拿到书面许可再定。上面"待定：天地图瓦片能不能离线缓存"仍然待定，指的是预先下载，不是这里按缓存头的缓存。
