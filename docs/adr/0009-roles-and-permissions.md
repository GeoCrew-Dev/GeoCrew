# 0009 身份与权限

## 背景

v0 只有组长、成员、只读三种角色。负责人要的是类似 Discord 的做法：组长权限最高，可以转让；默认有组长和组员两个身份；组长可以新建身份，并给各个身份（包括组员）开放不同的权限。

## 决定

- **组长**：只有一个，拥有全部权限，不受任何设置限制，可以转让。组长丢了手机时，由服务端管理员用命令行把组长转给别人。
- **组员**：每个人都有的基础身份，组长可以改它的权限。
- **自定义身份**：组长可以新建身份，比如副组长、采样员、访客。一个人可以有多个身份，权限合在一起算。
- **身份有上下顺序**：有"管理身份"权限的人，只能管排在自己下面的身份和成员，也不能把自己没有的权限给别人。
- **图层级覆盖**：可以单独设置某个图层哪些身份能看、能改、能删。
- **"只改自己的"**：编辑、删除要素都可以设成"全部"或"只限自己建的"。
- **安全相关的权利任何身份都关不掉**：发紧急求助、回应点名、报外出和返回、退出工作组、开关自己的位置共享。
- **权限清单**，二十项左右，分组显示：
  - 工作组：管理成员、管理身份、修改工作组（改名、归档）、修改共享设置、发公告；
  - 图层：新建和删除共享图层、修改结构和样式、编辑要素（全部 / 仅自己的）、删除要素（全部 / 仅自己的）、审核、指派任务；
  - 交流：发消息、发起点名、删除别人的消息；
  - 位置：查看组员位置；
  - 数据：导出和下载整组数据、生成网页查看链接、生成 AI 读写链接；
  - 插件：安装和启用插件。
- **操作日志**：改权限、分配身份、移出成员、转让组长都记进日志，组长可以查。
- **离线被拒的修改不丢**：离线时做的修改，联网后如果因为权限变了被服务端拒绝，就留在手机上，标为"未能提交"。
- **AI 和网页查看链接都按生成者本人的权限执行。**
- **分期**：协议和服务端在 v0.1 就一次做全。界面先只给预设：组长、组员、只读，外加"图层只读"。自定义身份的编辑器放到 v0.3 以后。
- **测试**：权限判断用一份 Go 与 Kotlin 共用的测试样例。

## 理由

Discord 的模式已经被大量用户验证过，也能覆盖"按图层设谁能改"。界面分期做，是为了不让野外小组一开始就面对一套很重的设置。

## 代价与后果

- 服务端每个接口都要按权限判断。客户端离线时还要自己再判断一遍。
- 权限模型越复杂，测试样例就越要完整。
