# 0017 地图应用的结构：一棵图层树、一个工具注册表

- 状态：已采纳（2026-11-28）
- 相关：[ADR 0004](0004-project-storage.md)、[ADR 0006](0006-rendering-and-styles.md)、[ADR 0010](0010-action-registry.md)、[ADR 0012](0012-plugins.md)、[ADR 0015](0015-map-sources.md)、[ADR 0016](0016-android-stack.md)

## 背景

同勘要做两大块：完整的 GIS 工具（像 QGIS：图层、样式、处理、属性编辑、导入导出、坐标系），和野外地图工具（多种图源、离线瓦片、导航交接、GNSS 状态、轨迹、测量、书签）。两块都不小，手机上能参考的很少，而且大量重合：图层、样式、测量、坐标系、地图视图、菜单和工具栏。

负责人 2026-11-28 提出两点：

- 图层不该硬分成点、线、面，加要素应该是"选图层、选点线面"；
- 图层列表默认折叠，只显示少量信息（图例），操作放进右侧的"更多"菜单，像 QGIS 右键图层的菜单。

这两点和 GIS、地图两块怎么合并一起考虑。方案请 Fable 评估过。

## 决定

### 一个应用，两套工具

GIS 和野外地图是同一个地图应用里的两套工具，共用一棵图层树和一个工具注册表，不是两个产品。

### 几何：一张表一种几何，界面上先选点线面

存储仍然是一张表一种几何类型，ADR 0004 和协议 v1 §7.1 不变。理由：

- QGIS 打开混合几何（`GEOMETRY`）的 GeoPackage 表时，本来就会按类型拆成最多三个子图层，分别设样式、分别编辑；
- Shapefile 装不下混合几何，导出时总要拆；
- 桌面 GIS 普遍按单一几何类型的表来处理；
- 协议 v1 的 `geometry_type` 只有六种单一类型和 `None`，建好后不能改。

负责人要的流程照做：

- **加要素**：打开一个面板，顶上是"点 | 线 | 面"（记住上次的选择），下面是能放这种要素的图层，"新建图层"也按选中的种类预设。不再先想"这是什么类型的图层"。
- **矢量图层组**（随图层树做）：
  - "新建矢量图层"建一个组，组只管显示，像 QGIS 的组；
  - 组里的点、线、面三部分在第一次用到时才建出来，按已有的"建一个同样的图层"复制字段；
  - QGIS 看到的仍是普通的单一几何的表，组内不强制字段一致；
  - 组内三部分默认用同一个颜色。
- **导入的 `GEOMETRY` 图层**：照常能用，加要素时三种都能放进去。不主动新建这种图层。它在工作组里怎么同步（加入时按类型拆开，还是给协议 v1 加 `Geometry`）到 M3 做客户端同步时再定，见待办。

### 共用的模型（纯 Kotlin 的 `core:*`）

- **`core:layers`**：一棵图层树。
  - 节点有：组、矢量、栅格、底图（瓦片图源）、叠加（实时轨迹、GNSS 位置、测量草图、书签）。
  - 顺序、显隐、透明度和图例的模型都在树上。
  - 现在这些分散在 `geocrew_layer_display`、`geocrew_rasters` 和 `basemap:*` 里，栅格还写死在所有矢量下面。先把它们合成一棵树。
- **`core:style`**：样式 JSON、分类（唯一值、分级）和图例生成，从 `StyleDialog.kt`、`LayersScreen.kt` 搬出来。以后的制图渲染（ADR 0006）也用它。
- **`core:geometry`**：长度、面积、方位、捕捉和节点编辑的计算，从 `Measure.kt`、`Snapping.kt`、`Drawing.kt` 搬出来。测量工具和长度、面积字段都用它。
- **`core:tools`**：取代 `MapTool` 枚举。
  - 一个工具就是一个动作（ADR 0010）加入口信息：分组、图标、适用于哪些图层种类、方式（立即执行、地图上交互、打开页面）。
  - 菜单、工具栏编辑、图层的"更多"菜单和 AI 的说明书都从注册表生成。
  - ADR 0010 本来就要求动作声明输入、输出的图层类型和界面入口。

### 安卓模块

- `:storage`：不变。
- `:map`（新）：
  - MapLibre 视图，以及把图层树画到 MapLibre 上的渲染；
  - 一个 `MapInteraction` 接口，画、测、拾取、捕捉都做成可替换的模式；
  - 借此把 `MapScreen.kt` 拆开。
- `app`：页面和组装。

### 处理工具和插件

- GDAL 的算法自动注册成动作。
- 参数表单按动作的 JSON Schema 统一生成，图层选择框按声明的输入类型过滤；结果是图层树里的一个新图层。
- 插件（ADR 0012）用同一种清单注册，出现在同样的菜单里，不另做界面。

### 图层列表

- **折叠的一行**（默认），从左到右：拖动手柄（≡）、图例色块（分类样式时显示种类图标）、名称（带数量和"有未保存的修改"的小点）、显隐、"更多"（⋮）。手柄在左、眼睛挪到 ⋮ 左边是负责人 2026-11-28 定的；不能拖的行（栅格、底图）留出手柄的位置，名称对齐。
- **点开这一行**：完整图例（各类别或各级）和不透明度。
- **按住手柄拖动**：排顺序，只在同一层里换位置（顶层之间、同一组的图层之间），拖到边缘停一会儿列表就滚动；进出分组用"移到分组"。
- **其余操作都在"更多"菜单里**：
  - 矢量图层，依次是：
    - 缩放到图层；
    - 属性表；
    - 样式（标注在样式里）；
    - 字段；
    - 导出；
    - 建一个同样的图层；
    - 改名；
    - 属性（坐标系、范围、数量、来源）；
    - 删除（放最后，用错误色，要确认）。
  - 栅格：缩放到图层、显示方式（灰度、山体阴影、分层设色）、属性、移除。
  - 底图：换图源、下载离线区域、移除。
  - 组：加点、线、面部分，改名，缩放到组，移除。

### 顺序

1. 加要素先选点线面（不改存储）。
2. 图层列表改成折叠行和"更多"菜单。
3. 统一的图层树，含分组（同时做成"矢量图层组"）。
4. 工具注册表取代 `MapTool`，图层的"更多"菜单从注册表生成。
5. 拆出 `:map` 和 `MapInteraction`，拆开 `MapScreen.kt`。
6. `core:style` 和图例。
7. 野外地图部分：图源（ADR 0015）、离线瓦片、GNSS 状态、导航交接。这些都小而看得见。
8. 处理工具：先做统一的参数表单，再接 GDAL 算法。
9. 插件。

## 补充

2026-11-28 补充：分组的第一版。
- **存储**：
  - 分组存在工程里：`geocrew_layer_groups` 记 id、名称、是不是矢量图层；
  - 显示表加了 `parent` 列，图层进了组时才加上，老工程打开时不写；
  - 组自己的位置和显隐是显示表里的一行（`group:<id>`）；
  - 和显隐一样只在这台手机上，不同步。M3 时再定要不要在工作组里共享。
- **排序**：逻辑在新的纯 Kotlin 模块 `core:layers`（`LayerTree`）。
  - 组不嵌套；组内的图层画在一起，画在组所在的位置。
  - 隐藏一个组，组内图层都不画；各图层自己的开关保留。
  - 已经排过顺序的工程，新图层放在最上面；没排过的，仍按建立的先后。
- **动作**：
  - `layer.group.create`、`layer.group.rename`；
  - `layer.group.remove`：组没了，图层留在组原来的位置；
  - `layer.group.display`；
  - `layer.move`：把图层或组移到顶层或某个组里的某个位置；
  - `layer.order` 照旧能用，组内的图层仍留在组里。
- **还没做**：
  - 栅格和底图还不进这棵树，仍画在矢量下面；和矢量混排随渲染改造（`:map`）做。
  - 矢量图层组：点、线、面部分第一次用到时自动建，下一步做。

2026-11-28 再补充：矢量图层组。
- **加要素**：面板顶上选点、线、面，下面列出所有显示着的矢量图层，矢量图层组算一项（用组名）。
  - 已有这种部分的，显示数量，点了直接加进去。
  - 还没有的，显示"新建线图层"这类字样，点了就建好部分再开始画。
  - 某种部分被隐藏了，这一项不列。
- **建部分**：动作 `layer.part.create`。
  - 新部分复制原图层的字段（连同值域）、坐标系和样式；原图层没有自己的样式时，用它现在显示的颜色。
  - 名称是"组名 线"这样（英文 points、lines、areas），重名时编号；放在组的最后。
  - 原图层是野外点、线、面模板的，新部分换成对应种类的模板；别的模板（轨迹）不带过去。
  - 原图层还不在矢量图层组里的，先建一个以它命名的组，放在它原来的位置。
  - 混合几何的图层三种都能放，不需要部分。
- 新建分组也改为放在其中第一个图层原来的位置，不再一律放在最上面。
- 图层页里，矢量图层组用"图层"图标，和普通分组的文件夹区分。

## 后果

- 好处：
  - 两套工具共用图层、样式、测量和地图视图，不重复写；
  - 菜单、工具栏、图层菜单和 AI 说明书出自同一个注册表，加一个工具只写一处；
  - 存储和协议不变，和 QGIS 互通。
- 代价：
  - 统一图层树要迁移现有的显示表（`geocrew_layer_display`、`geocrew_rasters`）；
  - 拆 `MapScreen.kt` 是一次较大的重构，要分几个 PR 做。
- 待定：
  - 导入的 `GEOMETRY` 图层怎么同步（M3 前定）；
  - Shapefile 导出的排期；
  - 工具栏先保持一个默认、由用户自己改，不做"野外""GIS"两套预设，等用户反馈再说。
