# 0004 工程存储：每个工程一个 GeoPackage

## 背景

旧版的所有工程共用一个 Room 数据库，几何存成 GeoJSON 文本，以"记录"为中心，没有图层，也没有空间索引。要做完整的 GIS，数据就得改成以图层为中心。

## 决定

- **每个工程一个文件夹**：`/sdcard/GeoCrew/工程/<名称>/`，里面有工程的 GeoPackage 和 `附件/` 目录。
- **以图层为中心**：工程由图层组成。每个图层有几何类型、字段、坐标系、样式和表单。
  - 字段带稳定的 ID，改名不影响同步合并，见 [ADR 0008](0008-sync-and-merge.md)。
  - 每个图层可以用任意坐标系，按原坐标保存。
- **图层模板**：地质点、路线、剖面、钻孔等做成内置的图层模板。野外定点仍保留专门的快捷流程，底层写进"地质点"图层。
- **附件**：
  - 文件放在 `附件/` 下，按 SHA-256 命名，同一个文件只存一份，同步也只传一次。
  - GeoPackage 里有一张附件表，用"关联表扩展"（Related Tables Extension）登记成一对多关系。
- **导出附件**：
  - GeoPackage：可以选"附件打包进库"；
  - KMZ：照片打包进去；
  - Shapefile、GeoJSON、CSV：在字段里写相对路径，附件放在旁边的文件夹，一起打成 zip。
- **数据安全**：
  - GeoPackage 里记录格式版本；
  - 打开工程时检查完整性；
  - 每天用 SQLite 的备份接口自动做一份快照，保留最近 N 份；
  - 从 v0.1 起，升级不丢数据，迁移都有测试。
- **SQLite 的设置**（M1 验证补充）：
  - 工程 GeoPackage 用 WAL 日志模式。SQLite 默认的 DELETE 模式在 /sdcard 上每次提交都要经过 FUSE 建、删日志文件，逐条保存慢 10 倍。
  - 同步级别明确设成 FULL（`OGR_SQLITE_SYNCHRONOUS=FULL`），每次保存都 fsync，突然断电也不丢已保存的点；实测每条约 2 ms。GDAL 对新建的文件默认不做 fsync，不设的话断电时可能损坏刚导入的文件。
  - 导出、分享或拷贝工程前先做 WAL 检查点；工程开着时，最近的修改还在 `-wal` 文件里。
  - 导入时先把要素写完，再执行 SQL：在写入前执行的 SQL 会让 GDAL 提前建好空间索引，逐条维护，慢十几倍。
- **同步中的工程只由应用写入**。外部程序只能读；要改，就改导出的副本。因为用 WAL，外部程序要读的是已关闭或刚做过检查点的工程；工程开着时直接读 `.gpkg`，会看不到还在 `-wal` 里的修改。
- 旧版的 Room 数据不做迁移，因为是重写，也没有用户。

## 理由

- GeoPackage 是 GDAL 的原生格式，带空间索引，桌面 GIS 能直接打开，符合"开放格式、数据自主"的原则。
- 一个工程一个文件夹，方便拷贝、备份、交给别人。

## 代价与后果

- /sdcard 和外置卡都走 FUSE。M1 在模拟器上实测：用 WAL 时逐条保存一个点约 2 ms（私有目录 1.3 ms），导入 10 万点约 0.3 秒，随机杀进程后都能完整恢复，见[验证报告](../spikes/m1-gpkg-sdcard.md)。
- FAT32 的卡上单个文件最大 4 GB。
- 退路：真机上如果明显变差，工作库放在应用私有目录，/sdcard 上放自动导出的副本。
- 待定：同步用的元数据放在 GeoPackage 的扩展表里，还是放在单独的文件里，M2 设计编辑缓冲时一起定。

## 状态

已采纳（2026-11-25）。M1 在模拟器上验证通过，见[验证报告](../spikes/m1-gpkg-sdcard.md)；2026-11-26 在 S24 Ultra 真机上复测，结论不变。exFAT 存储卡要等有带卡槽的手机，放到以后。

2026-11-26 补充：编辑缓冲按 QGIS 的逻辑做，日志放在应用私有目录，不进 GeoPackage，见 [ADR 0005](0005-edit-buffer.md)。同步用的元数据放在哪里，改到做客户端同步（M3）时再定。

2026-11-26 补充：工程的文件格式第 1 版。
- 工程文件夹里的 GeoPackage 叫 `<工程名>.gpkg`。工程名按 FAT 和 exFAT 存储卡的规则检查：不能有 `\ / : * ? " < > |`，不能以空格或点结尾，最长 64 个字符。
- 同勘自己的三张表：`geocrew_project` 记格式版本、工程 ID、名称和创建时间；`geocrew_layers` 记每个图层的 ID 和来自哪个模板；`geocrew_fields` 给每个字段一个稳定的 ID。这三张表不登记到 `gpkg_contents`，桌面 GIS 打开时看不到。
- 打开工程时用 `PRAGMA quick_check` 检查完整性，格式版本比应用新的拒绝打开。
- 内置模板先只有"地质点"（CGCS2000 经纬度，EPSG:4490），字段是草案，负责人野外用过后再定。路线、剖面、钻孔下面还挂着测点、分层这类子记录，需要稳定的行 ID，随各自的工具一起做。

2026-11-26 补充：负责人指出定点不只是地质人员在用，水文地质就不测产状。内置的点图层改成通用的"野外点"（英文 Field points），只带点号、描述、海拔、定位精度、记录时间、记录人；其余字段由用户自己加（动作 `layer.field.add`）。可加的类型现在有文字、数字、整数、日期、是/否；照片、视频、录音、文件这类字段随附件一起做。图层名和字段名用建工程时应用的语言（中文或英文），应用靠模板里的字段键（如 `number`、`time`）认出它们，不管是哪种语言。

2026-11-26 更正：上面说同勘自己的三张表"桌面 GIS 打开时看不到"，不对。GDAL 的 GeoPackage 驱动在 `gpkg_contents` 里没有登记非空间表时，会把没登记的表也列出来，所以 QGIS 里能看到这三张表，不影响使用。导出 KML 时用打开选项 `LIST_ALL_TABLES=NO` 把它们排除在外。

2026-11-26 再补充：负责人又精简了默认字段。"野外点"只带点名、描述两个字段（字段键 `name`、`description`），坐标就是点的几何，不另设字段；海拔、定位精度、记录时间、记录人都去掉了，要的用户自己加。字段在"工程设置"里管理。主页卡片上的地图缩略图存在应用私有目录（`thumbnails/<工程名>.jpg`），不放进工程文件夹，新建同名工程时删掉旧的。

2026-11-26 再补充：负责人定了新建工程不带图层，图层由用户新建（动作 `layer.create`）。现在只能建点图层，字段来自"野外点"模板，坐标系是 CGCS2000 经纬度；选坐标系放到做坐标换算时。第一次定点时工程里没有点图层，就先弹新建窗口，默认名"野外点"。图层在地图上按建立的顺序各用一种颜色，等有了图层样式（ADR 0006）再换。"记住此选项并不再提示"选中的定点图层只存在这台手机上（按工程 ID 和图层 ID），不写进工程文件。
