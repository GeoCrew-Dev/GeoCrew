# 0012 插件

## 背景

GIS 生态需要插件。但 QGIS 的 Python 插件依赖 PyQGIS 和 PyQt，就算把 Python 移植到手机上也跑不起来，所以我们要建自己的插件体系。负责人的设想是：开一个专门的收录仓库，定一套不强制的标准，符合的才收录，插件要自带说明书，让 AI 能找到。

## 决定

- **运行时**：JS / TS 插件在 QuickJS 这类沙箱里运行。
  - 插件 API 是纯异步的消息接口。
  - 调试在电脑上做：在 Node 里连接无界面宿主；手机上只看日志和热重载。
  - 计算量大的算法留作内置动作。
- **清单**：每个插件都有一份清单，带上和内置动作同一格式的说明书。装上之后，插件提供的工具进入动作注册表和 AI 手册，见 [ADR 0010](0010-action-registry.md)。
- **权限**：
  - 安装时授权，之后可以撤销；
  - 插件工具的风险分组，由宿主按它申请的权限推出一个下限，插件不能自己往低报；
  - 身份权限里有一项"安装和启用插件"，见 [ADR 0009](0009-roles-and-permissions.md)。
- **收录**：
  - GeoCrew-Plugins 仓库参照 Obsidian 的做法：仓库里只放目录，插件代码放在作者自己的仓库，作者提交 PR 申请收录。
  - 安装来源有三种：官方目录、工作组目录、本地文件。
- **标准分三层**：
  - 引擎约定：必须满足，否则加载不了；
  - 收录要求：进官方目录必须满足；
  - 质量指南：不强制，符合的标"推荐"。
- **安卓原生能力**不直接开放给脚本插件，而是封装成宿主接口，包括定位、传感器、相机、蓝牙串口、USB 串口、NFC 等。
- **真要用原生代码的**，做成独立的安卓应用插件，通过绑定服务和同勘通信。
- **以后再做**：Python 分析内核、WASM。
- **插件 API 的版本**：核心稳定之前，插件 API 一直是预览版。

## 理由

- JS 沙箱体积小，能可靠隔离，跨平台，AI 也很会写。
- 说明书格式和内置动作统一，AI 找插件工具的方式就和找内置工具一样。

## 代价与后果

- QuickJS 没有 JIT，也没有调试协议，所以调试要放到电脑上做。
- 生态要从零开始建：先用三个官方插件验证接口。

## 状态

草案。等技术验证确认 QuickJS 的性能和调试方式。这项不在 v0.1 的关键路径上。
