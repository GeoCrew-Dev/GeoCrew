# 0010 动作注册表

## 背景

要让 AI 能操作全部功能，前提是所有功能都能被统一调用。旧版只登记了 16 个动作，另有 11 个文件绕过动作层直接改数据。同一个动作还会同时被界面、AI、插件、MCP、自定义按钮、规则，以及同勘灵宝的训练数据用到，改一处，很多地方会一起坏。

## 决定

- **所有界面操作都是动作。** 界面按钮调用动作，不直接改数据。从单机骨架（M2）的第一天起就这样做。
- **只有一个注册表**：内置功能、GDAL 算法（自动登记）、插件、AI 和 MCP 都用它。
- **每个动作要声明**：名称、说明、参数（JSON Schema）、输入输出的图层类型、风险分组、在界面上的入口、稳定级别、用法示例。
- **风险分组**：查看、修改、批量、删除、对外发送、改设置。
  - 用户可以改某个动作属于哪一组，也可以让 AI 来改（改之前先确认）。
  - 怎么改都超不过本人的身份权限和组长设的限制。组长锁定的动作，组员改不了。
- **稳定级别**：稳定、预览、内部。
  - 只有"稳定"级的动作开放给插件、MCP 和训练数据。
  - 稳定动作的参数只能增加、不能修改；改名时保留旧名作为别名。
- **给 AI 的手册**从注册表自动生成，分三层：
  - 每次都带上：操作总说明、分组目录、十几个常用工具；
  - 按需加载：某一组的动作列表；
  - 用到时才加载：单个动作的完整说明。

  另外有"完整版手册"选项，适合上下文很大、带缓存的模型。
- **撤销、权限检查、操作日志**只在注册表这一处实现。

## 理由

一处登记，界面表单、AI 调用、插件接口和 MCP 就都有了；靠稳定级别保证外部调用方不会被改坏。

## 代价与后果

- 写界面时必须先登记动作，不能图省事直接改数据。
- 稳定动作的兼容性要长期维护。

## 状态

已采纳（2026-11-25）。
