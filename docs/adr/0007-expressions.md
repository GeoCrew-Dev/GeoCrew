# 0007 表达式统一用 SQL

## 背景

字段计算、筛选、默认值、约束、按规则着色和标注，都需要表达式。如果样式用 MapLibre 的表达式、计算用 SQL，就会有两套语言，写法也不一致。负责人的要求是有类似 QGIS 的功能，但不要求和 QGIS 的表达式写法兼容。

## 决定

- 只用一种表达式语言：SQL，采用 SQLite 的写法，再加上我们注册的几何、文字、数学和日期函数。
- 字段计算、筛选、默认值、约束、按规则着色、标注内容，都用它来写。
- 样式和标注在生成地图瓦片时就用 SQL 算好，MapLibre 只读取算好的属性。制图渲染器也用同一套。
- 外部数据源用 GDAL 的 SQLite 方言执行同样的 SQL，所以就地编辑的 Shapefile 也能用。
- AI 可以把用户的一句话翻译成表达式。

## 理由

- 工程本来就是 SQLite（GeoPackage），用 SQL 最直接，不用再写一个表达式引擎。
- 一种语言贯穿各处，文档、AI 和用户只需要学一套。

## 代价与后果

- 写法和 QGIS 的表达式不一样（这本来也不是目标）。
- 我们注册的函数要有完整的文档和测试。
- 性能依赖 SQLite 的查询。复杂的表达式在大图层上可能慢，以后可能要缓存计算结果。

## 状态

已采纳（2026-11-25）。

2026-11-27 补充（负责人定）：数字字段的取值范围不写成 SQL 表达式，而是存成 GeoPackage 标准的字段值域（见 ADR 0004 的补充），这样 GDAL 读得出来、QGIS 也能通过 GDAL 读到，字段改名也不用改表达式。上面说的"约束"指以后要做的一般约束（跨字段、按条件），仍然用 SQL 写。
