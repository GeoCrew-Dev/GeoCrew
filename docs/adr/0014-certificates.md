# 0014 服务端证书

## 背景

安卓客户端只走 HTTPS。大多数野外队伍没有域名，国内云服务器用域名对外提供服务还要先备案。

## 决定

- **默认用自签证书**：服务端第一次启动时自动生成自签证书。邀请二维码里带上它的公钥指纹（SPKI），手机只认这个公钥。
  - 固定的是公钥，不是整张证书，所以证书续期、IP 变了，都不用重新邀请；IP 变了，只要在手机上改一下服务器地址。
- **可选正式证书**：有公网 IP 的服务端，可以用 ACME 自动申请 Let's Encrypt 的 IP 证书。这项服务 2026 年 1 月正式可用，证书有效期约 6 天，必须自动续期。
- **有域名的**照样可以用正式证书，比如放在 Caddy 等反向代理后面。

## 理由

自签证书加公钥固定，不依赖域名和证书机构就能安全连接，部署最简单。

## 代价与后果

- 浏览器打开网页查看页时会报证书警告，大多数桌面 MCP 客户端也不接受自签证书。需要这两样的，用 IP 证书或域名证书。
- "用 IP 加端口就不用备案"只是常见做法，不是法律结论，文档里不能写成承诺。
- 家用宽带大多没有公网 IPv4，实际一般需要一台云主机。
- 待定：国内云服务商是否放行 ACME 验证所需的 80 / 443 端口，还没核实。

## 状态

已采纳（2026-11-25）。

2026-11-28 补充：服务端实现了自签证书（`-tls`，默认 `self`）。第一次启动时生成 ECDSA P-256 的密钥和一张 20 年的证书（手机只固定公钥，证书本身的期限无关紧要），存在数据目录的 `tls/`（私钥只有服务端用户能读）；之后每次启动沿用，日志打印公钥指纹（SPKI 的 SHA-256，base64url 不带填充）。`-tls files` 用现成的证书文件；`-tls off` 是明文，只用于 HTTPS 反向代理后面和本机测试，一致性检查在 CI 里这样跑。工作区信息（协议 5.1）带上 `fingerprint`。Let's Encrypt 的 IP 证书（ACME）还没做。
