# 0006 渲染与样式模型

## 背景

实时地图要流畅，出图又要能用任意投影、输出矢量 PDF，还要画得准地质符号。MapLibre 是网络地图引擎：只能显示 Web 墨卡托，符号按像素计算，导出时只能截图。它满足不了出图的要求，但做实时地图很流畅。

## 决定

- **实时地图用 MapLibre Native**：
  - 工程图层通过 CustomGeometrySource 交给 MapLibre：按瓦片范围查空间索引，重投影，再用 SQL 算好样式属性，见 [ADR 0007](0007-expressions.md)。
  - 如果不够快，再改成自己编码 MVT 瓦片。
- **非 Web 墨卡托的栅格和 WMTS**（如天地图经纬度瓦片、高斯投影的 GeoTIFF）：先用 GDAL 重投影成瓦片，再交给 MapLibre 显示。
- **另做一个制图渲染器**：
  - 直接画到 Android 的 Canvas 和 PdfDocument 上，用 PROJ 支持任意投影，输出矢量 PDF；
  - 符号按毫米或地图单位计算，花纹随地图比例尺缩放；
  - 能画沿线符号，比如逆断层的齿；
  - 标注能避让，能加引线。
- **两个渲染器共用一套样式模型**。v1 只收两边都能实现的部分：
  - 着色方式：单一、分类、分级、按规则（规则用 SQL 条件）；
  - 几何类型：点、线、面，外加标注；
  - 另配一个地质符号库。

  只有出图才用得上的属性单独标出来。
- **用截图对比测试把两边的差异控制住。**
- **三维以后做**：用 WebView 加 MapLibre GL JS 做只读视图。MapLibre Native 到 2026 年仍然没有正式的三维地形。
- **实时等高线**：用 GDAL 从 DEM 生成。

## 理由

实时操作和精确出图对引擎的要求不一样，各用合适的引擎；靠同一套样式模型，两边画出来保持一致。

## 代价与后果

- 要维护两个渲染器。两边的标注引擎不同，画出来不会完全一样，靠截图对比测试约束差异。
- 制图渲染器的标注引擎是我们自己写的，起步时质量不会太高。

## 状态

已采纳（2026-11-25）。M1 要验证两项：

- 用 CustomGeometrySource 显示 10 万要素和编辑后的刷新：在模拟器上验证可行，低缩放级别要抽稀或聚合，见[验证报告](../spikes/m1-map-customgeometry.md)；
- 非 Web 墨卡托栅格的显示：在模拟器上验证可行，GDAL 按请求现场重投影成瓦片，经 OkHttp 拦截器交给 MapLibre，见[验证报告](../spikes/m1-raster-reprojection.md)。

2026-11-26 在 S24 Ultra 真机上复测，两项都通过：10 万点缩放约 100 至 110 帧 / 秒，栅格缩放 120 帧 / 秒（屏幕上限）。渲染后端用 MapLibre 的 OpenGL ES 版（`android-sdk-opengl`）：默认的 Vulkan 版在真机上同样流畅，但在模拟器上会崩溃，而开发和 CI 都靠模拟器。以后 Vulkan 版在模拟器上修好了再考虑换。

2026-11-26 样式模型的第一步：单一符号。每个图层一种颜色、点的半径、线宽和面的填充透明度，存在工程的 `geocrew_layer_style` 表里，一个图层一行 JSON（`{"kind": "single", "color": "#rrggbb", "size", "width", "fill"}`），以后的分类、分级、规则着色用别的 `kind`。没设样式的图层按建立的先后取一种颜色。动作 `layer.style`，改了马上存、不进撤销，和图层显示一样。

2026-11-27 栅格图层按 M1 验证的做法落地：MapLibre 的每个栅格源指向 `https://geocrew.tiles/raster/<栅格 ID>/<文件版本>/{z}/{x}/{y}.png`，应用给 MapLibre 装了自己的 OkHttp 客户端，拦截器拦下这个地址，调 GeoCrew-Native 的 `renderTile` 现场出瓦片，其他请求照常出去。地址里带文件的大小和修改时间，文件换了 MapLibre 的缓存就不会用旧瓦片；出图失败回空瓦片，不抛异常。8 位的灰度、RGB、RGBA 直接出图；调色板图先用 `gdal raster color-map` 转成 RGB，16 位、浮点的先用 `gdal raster scale` 拉伸成 8 位（单波段 DEM 可以选灰度、山体阴影、分层设色，见下），都写成 GDAL 管线（起初是 VRT，见下面 DEM 一段），存在应用私有目录，文件变了重做。栅格源带范围和缩放级别（从栅格只有几个像素大到瓦片像素和原像元一样细，再往上由 MapLibre 放大），画在所有矢量图层下面、底图上面，后加的在上面。OkHttp 原本就随 MapLibre 打包，现在应用直接引用同一版本（4.12.0）。

2026-11-27 分类着色：样式多了 `kind` 为 `categorized` 的一种，在单一符号的键之外加 `field`（图层的一个字段）和 `classes`（`[{"value", "color"}]`，每个值只出现一次，最多 100 个）。要素的这个字段等于哪个值就用那个颜色，其余的（包括空值）用样式本身的颜色，界面上叫"其他"。值按文字比较，数字字段也一样。样式页里切到"分类"、选字段，就按图层里现有的值依次分配颜色（自然排序，相邻的颜色尽量分得开，不用黑白）；再打开时保留原来的颜色，新出现的值接在后面。点大小、线宽、填充对所有类一样。字段改名或删掉后，样式里的类不再对得上，要素都按"其他"画。

2026-11-27 颜色带不透明度：样式里的颜色可以是 `#rrggbb`，也可以是 `#rrggbbaa`（最后两位是不透明度），分类的每一类也一样；不写后两位就是不透明。交给 MapLibre 时不透明的照旧写 `#rrggbb`，带不透明度的写成 `rgba(r, g, b, a)`。它和图层页的"不透明度"（整个图层显示得多透明）、面的"填充"相乘。

2026-11-27 标注设置：样式里的 `label` 指定用哪个字段标注要素，空字符串表示不标；没有这个键时照旧用名称字段（点名、名称）。点、线、面都按它标。`layer.style` 检查字段是否存在。

2026-11-27 分级着色：`kind` 为 `graduated` 的样式在单一符号的键之外有 `field`（数值字段：整数、长整数、实数）和 `ranges`（`[{"from", "to", "color"}]`，最多 100 个）。值落在 from 到 to 之间（不含 to，最后一级含 to）就用这一级的颜色，其余的（包括空值、不是数的）用样式本身的颜色。样式页里选数值字段、级数（2–9）、等距或分位数，按色带的起止两色（在 Oklab 里插值）生成各级颜色，每级也能单独改；分位数时相同的分界会合并。图层页展开后显示分类和分级的图例。

2026-11-27 DEM 的山体阴影和分层设色：单波段栅格在图层页可以选"灰度 / 山体阴影 / 分层设色"，存在样式表里（`{"kind": "raster", "render": "hillshade" | "relief"}`，以栅格 ID 为键，默认不存），动作 `raster.display` 的 `render`。山体阴影用 `gdal raster hillshade --variant multidirectional`（多方向光照，经纬度 DEM 由 GDAL 自己把度换成米），分层设色用 `gdal raster color-map` 按高程从低到高（绿、黄、褐、白）配色并带 alpha。显示用的文件都写成 GDAL 管线（`.gdalg.json`），出瓦片时现场算，不另存栅格；原来的调色板、拉伸也改成管线：在运行中新写的 VRT 有时要重启应用才画得出，管线没有这个问题。同一个栅格各种显示方式的文件都留着，只在源文件变了时删除，因为原生库按路径缓存打开的数据集，同一路径不能重写。

2026-11-27 字段改名和删除（`layer.field.rename`、`layer.field.delete`）：在同勘里给字段改名时，样式的 `field` 和 `label` 跟着改，类和分级照旧对得上；删掉字段时，按它分类或分级的样式回到单一颜色（颜色、点大小、线宽、填充保留），按它标注的回到默认的名称字段。在别的软件里改名或删掉的字段照上面说的：类对不上，要素按"其他"画。

2026-11-28 编辑者标签（负责人提的"特殊标签"，具体做法自己定）：团队工程的地图可以在每个要素的标注下面多显示一行小字，写最后修改它的人的昵称，自己改的写"我"；本来不标注的要素只显示这一行。开关是地图菜单"地图"组里的"编辑者"（也能放到地图边的工具栏），按工程记在手机上，没连团队的工程不显示。不做成样式里 `label` 可选的字段：那样会把点名换掉，而编辑者通常要和点名一起看。显示的是最后修改人，不是采集人：协议只记每个字段最后是谁改的（6.1），不记行是谁建的。编辑者怎么记见 ADR 0008 的第十一次补充。

2026-11-28 补充（负责人强调）：编辑者不算 GIS 字段，只是同勘给要素的特殊标记。它不进图层的表结构，只存在同勘自己的同步表里；不出现在属性表、表单、字段列表和标注字段的选项里，也不作为字段导出（整个工程导出成 GeoPackage 时，它跟着同勘自己的表一起在文件里，别的软件不列出这些表），别的 GIS 软件打开工程看不到它。以后同勘给要素加的别的标记（同步状态、冲突之类）也照这样：存在同勘自己的表里，由同勘的界面显示。

2026-11-28 冲突标记：团队工程里有未处理冲突的要素（协议 6.5），地图上在它上方显示橙色圆底白色"!"的标记（点在点的正上方，线、面在标注位置的上方），跟随图层的不透明度，不参与标注避让。数据来自冲突记录（`sync.conflicts`），不进要素属性。实现上标记图层的图片和不透明度都从要素属性取，和标注一样：用固定值时 MapLibre 不画图标。
