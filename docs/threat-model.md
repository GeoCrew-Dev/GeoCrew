# 威胁模型

> 状态：v0.1 前定稿，之后每加一个对外接口都要回来补充。

## 1. 要保护的东西

- **野外数据**：记录、照片、录音、样品。这些数据没法重采，有的还是保密的勘查成果。
- **工作组令牌和 AI Key**：泄露了，别人就能冒充组员，或者花掉用户的额度。
- **位置隐私**：组员的实时位置和轨迹。
- **设备本身**：应用持有"所有文件访问"权限。

## 2. 威胁与对策

| 威胁 | 例子 | 对策 |
|---|---|---|
| 损坏或恶意的文件 | 导入的 Shapefile、KML 让 GDAL 崩溃 | 在普通的独立进程里识别和解析，崩了只提示"文件无法读取"。这只能防崩溃，防不了漏洞利用。安卓的 isolatedProcess 拿不到任何文件，处理不了多文件格式，所以不用它 |
| 恶意插件 | 插件偷读数据，或者向外发送数据 | 插件在沙箱里运行，只能用声明过、用户授权过的接口；网络只能访问声明的域名；风险分组由宿主按权限推出下限；官方目录可以紧急下架有问题的版本，见 [ADR 0012](adr/0012-plugins.md) |
| 提示注入 | 记录、组内消息、导入图层的属性、插件说明书里藏着"指令" | 这些内容一律只当资料，不当指令；模型读了这些内容之后提出的修改，一律先确认；AI 触发的导出、分享、联网、删除，一律先确认，见 [ADR 0011](adr/0011-ai.md) |
| 手机丢失 | 别人拿到手机 | 令牌和 Key 只放在应用私有目录，用 Keystore 保护，不进 /sdcard，不进工程包，也不进分享出去的图源文件和二维码；组长可以吊销这台设备 |
| 网络攻击者 | 中间人截获同步内容 | 只走 HTTPS；自签证书的公钥通过邀请二维码固定，见 [ADR 0014](adr/0014-certificates.md) |
| 服务端运维人员不可信或好奇 | 偷看数据或 AI 对话 | 服务端由团队自己部署；AI 代理默认只记用量，组长开启查看对话内容时通知全组；推送通知里不带正文 |
| 服务端处理文件时崩溃 | 导出时 GDAL 崩溃 | GDAL 作为单独的辅助程序在子进程里跑，不会拖垮同步服务，见 [ADR 0013](adr/0013-server-gdal-helper.md) |
| 越权 | 组员想办法给自己加权限 | 权限由服务端判断；身份有上下顺序，不能把自己没有的权限给别人，见 [ADR 0009](adr/0009-roles-and-permissions.md) |

## 3. 不追求的

- **端到端加密**：服务端由团队自己部署，被视为可信。
- **防住解析器层面的漏洞利用**：我们只做崩溃隔离。
